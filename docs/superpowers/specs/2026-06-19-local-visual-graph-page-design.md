# Local Visual Graph Page Design

## Context

The reset renderer now writes a manifest-declared `artifact/data/graph.json` and exposes compact graph diagnostics in `_raya/inspect/index.html`. The old `main` branch graph had useful reader-facing capabilities: search, layout switching, group legend filters, fit/reset, focus-on-neighborhood, and click-through navigation. Its implementation is not acceptable for the reset framework because it depends on an Eleventy template, injected legacy data shape, Tailwind-oriented classes, and Cytoscape from a CDN.

This slice adapts the capability, not the stack. The result stays fully static, local, and generated by the Python renderer.

## Goals

- Add a browser-facing course graph page at `artifact/site/_raya/graph/index.html`.
- Add a `Graph` command in the top course bar on normal rendered pages.
- Use the existing generated graph index as the source of truth, without external requests or browser-side renderer dependencies.
- Provide the old-main core interactions in a reset-native form: search, group filter chips, layout modes, fit/reset, hover/focus neighborhood, and click-through page navigation.
- Keep graph internals out of normal article pages except for the top-bar command.
- Keep inspection graph diagnostics as an agent/professor/contributor surface.

## Non-Goals

- Do not import Cytoscape or any external graph library.
- Do not add CDN requests.
- Do not add dynamic study state, progress personalization, adaptive recommendations, or graph editing.
- Do not make the graph the default student landing page.
- Do not expose artifact-root `data/graph.json` as a broken browser link.

## Architecture

The builder generates one extra static page:

`artifact/site/_raya/graph/index.html`

The page embeds the current graph payload as JSON in:

```html
<script type="application/json" id="raya-graph-data">...</script>
```

This avoids fetch-path ambiguity between `artifact/data/` and `artifact/site/`. The artifact-level `data/graph.json` remains the canonical machine/agent surface. The embedded browser copy is a rendered view input, not a new authority surface.

The page loads local resources only:

- `../render/rich.css`
- `../render/skin.css`
- `../render/accessibility/open-dyslexic.css`
- `../render/accessibility/open-dyslexic-toggle.js`
- `../render/graph.js`

`graph.js` owns interaction only. It reads the embedded JSON, builds an inline SVG, and updates the DOM. It must not fetch remote code or remote data.

## Visual Model

The first implementation uses deterministic layouts rather than a physics engine:

- `map`: group columns by top-level unit, ordered by page order;
- `radial`: groups arranged around a circle, pages arranged within each group;
- `list`: a dense searchable index with edge counts and backlink counts.

This is less flashy than old Cytoscape, but it is stable, testable, fast, and fully local. A later slice can add a force-directed local algorithm after this foundation is verified.

## Interactions

The graph page includes:

- search input with accent-insensitive substring/prefix matching;
- layout select for `map`, `radial`, and `list`;
- group chips that hide/show top-level groups;
- `Fit` button that restores the default viewport for SVG layouts;
- `Reset` button that clears search, filters, selection, and layout back to `map`;
- clickable nodes linking to rendered pages;
- keyboard-focusable nodes;
- hover/focus highlighting for selected node, inbound/outbound edges, and neighboring nodes;
- status text showing visible nodes and edges.

The graph should remain usable without JavaScript by rendering a static list of page links below the graph controls. With JavaScript enabled, the list remains useful as the `list` layout and as a fallback.

## Builder Integration

`packages/static/src/raya_static/builder.py` adds:

- a `STATIC_GRAPH_PATH` constant;
- `_write_graph_surface(...)`;
- `_render_graph_surface(...)`;
- top-bar graph link generation using `_relative_href(page.output_path, STATIC_GRAPH_PATH.as_posix())`;
- graph page resource links using existing `_relative_href` rules.

`packages/static/src/raya_static/graph.py` adds:

- `GRAPH_SCRIPT_NAME = "graph.js"`;
- `GRAPH_RESOURCE_PATH = "_raya/render"`;
- `graph_resources()` returning the local JavaScript string.

The existing `_write_shell_resources()` pattern is reused for `_write_graph_resources()`.

## Styling

Graph CSS lives in `packages/static/src/raya_static/rendering.py` alongside current renderer CSS. It uses existing `--raya-*` skin tokens and must work across the Eva and accessibility skins.

The graph page uses a full-width workspace layout, not the article three-column reading shell. The visual area should prioritize desktop space while remaining usable on mobile.

## Tests

Contract tests:

- Building the render fixture writes `_raya/graph/index.html` and `_raya/render/graph.js`.
- Normal pages include a relative top-bar link to the graph page.
- The graph page embeds graph JSON, links only local static resources, includes controls, and does not reference Cytoscape, CDN URLs, or artifact-root `../../data/graph.json`.
- The local graph JS contains the expected interaction hooks: search, layout selection, group filter, fit, reset, and node navigation.

Static/e2e tests:

- Preview serves `_raya/graph/index.html` and `_raya/render/graph.js`.
- Browser rendering opens the graph page at desktop and mobile viewports with no horizontal overflow.
- The SVG/list contains graph nodes.
- Search filters visible nodes and updates status.
- Layout select changes the active layout.
- Reset restores visible nodes.
- Clicking/focusing a graph node exposes navigation target without external requests.

Verification:

- `UV_PROJECT_ENVIRONMENT=.venv-local uv run pytest tests/contracts/test_static_builder.py::test_build_writes_local_visual_graph_surface -q`
- `UV_PROJECT_ENVIRONMENT=.venv-local uv run pytest tests/e2e/test_preview_static_read_path.py::test_preview_serves_local_visual_graph_surface -q`
- `./scripts/check-render-debug.sh`

## Risks

- Browser graph data must not depend on fetching `artifact/data/graph.json`, because static preview/deploy serve `artifact/site/`.
- The graph page must not introduce an accidental renderer dependency or CDN path.
- SVG layout needs deterministic dimensions so browser tests can assert nonblank, bounded output.
- The visual graph is a learning aid, not an authority surface; machine truth remains in manifest-declared artifact data.
