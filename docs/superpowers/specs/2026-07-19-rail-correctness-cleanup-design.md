# Reader-Rail Correctness Cleanup — Design

Date: 2026-07-19
Status: Approved for planning
Supersedes scope of: `2026-07-17-rail-collapse-single-source-of-truth-design.md` (follow-on)

## Context

The rail-collapse single-source-of-truth rebuild (PR #15) shipped and is deployed. A
user then reported the collapsed left rail still rendering broken. Four independent
adversarial reviews were run to establish ground truth before any further work.

The reviews confirmed the reported breakage is **stale assets**, not a live bug — but
they also refuted three claims made after the rebuild and surfaced real defects the
original cleanup design did not cover. This spec is scoped from the corrected picture.

## Findings that drive this design

### The reported breakage is stale assets (diagnosis survived attack)

The screenshot showed two symptoms from two different sources, both fixed on the same
day, which is the signature of a client serving a stale asset pair:

- `"Expand map"` text on both toggle buttons is generated by `shell.js` at runtime. It
  was removed in `4927c11` (2026-07-13): `"Collapse map"/"Expand map"` →
  `"Hide map"/"Map"` (`packages/static/src/raya_static/shell.py:132,135`). Current
  emitted JS does not contain `"Expand map"`.
- The vertical per-character `"OpenDyslexic"` label was fixed in `53cc021` (same day) by
  adding `hyphens: none; overflow-wrap: normal; word-break: normal`
  (`packages/static/src/raya_static/rendering.py:6759-6763`).

Current code cannot render the reported layout: `.raya-course-map-expand { display: none }`
(`rendering.py:4089-4091`) makes a second map button structurally impossible while expanded.

Sweeps that came back clean: 14 widths (640-1920), real button clicks, seeded
sessionStorage, OpenDyslexic + x-large text, `prefers-reduced-motion`, JS blocked,
prepaint blocked, deviceScaleFactor 1.5/2/3, landscape, resize sequences.

**Caveat retained:** stale browser cache and a stale *build* are observationally
identical. They were separated only by confirming the live deployed bytes contain the
post-fix markers.

### Untested engine class is a plausible real bug (drives Workstream 1)

Firefox and WebKit are not installed, so both the probe and the reviews covered Chromium
only. The JS rail-state derivation keys off `innerWidth`
(`shell_prepaint.py:19,24`; `shell.py:227`) while the collapse rules live inside
`@media (min-width: 640px)` (`rendering.py:6704`, rules at `:6776-6780`).

On any engine where media-query width excludes a classic scrollbar, an `innerWidth` in
`[640, 640 + scrollbarWidth)` places JS in the structural band (state → `collapsed`)
while CSS is still below the band (body not hidden) — producing exactly the reported
symptom shape. Chromium was verified to have exact agreement at 639/640/641/645/650/
655/660/893/894/900, so this is engine-specific and currently unfalsified.

### Single-source-of-truth was overclaimed (drives Workstreams 2 and 3)

Verified hardcoded boundaries outside `shell_geometry.py`:

- `@media (max-width: 639px)` × 3 — `rendering.py:4100`, `:5261`, `:6229`. `_TOKENS`
  (`shell_geometry.py:34-40`) has `__RAYA_APPROVED_MINUS_PX__` but no
  `__RAYA_STRUCTURAL_MINUS_PX__`, so 640 is single-sourced on the `min-width` side only.
- `@media (min-width: 1280px)` at `rendering.py:5166`, while `:5370` uses the token for
  the same boundary.
- `(max-width: 767px)` duplicated across `rendering.py:6863` **and** `shell.py:55` — a
  fourth rail boundary with no token, duplicated in CSS and JS. This is the exact failure
  mode the rebuild claimed to eliminate.
- The default-state rule is written three times: `shell_prepaint.py:24`,
  `shell.py:172-177`, `shell.py:178-183` (the last two are verbatim copies).

Nine element-mirror **reader** selectors survive in shipped CSS
(`rendering.py:4157, 4161, 4167, 4182, 4193, 5358, 5364, 6574, 6576`). The mirror
*writes* were removed in `450eed5`, so these are currently dead — but one line of JS
restoring a mirror write resurrects all nine.

### The guardrail tests are partly vacuous (drives Workstream 3)

- `test_collapse_selectors_key_off_html_only` (`tests/e2e/test_rail_collapse_contract.py:102-103`)
  skips any line containing `-transition`. All nine surviving mirror selectors contain
  `-transition`, so the test reports zero offenders. Removing the skip yields 9 offenders
  while the suite stays green.
- `test_css_and_js_share_the_same_rail_boundaries` asserts only that tokens are
  **present**; it never asserts hardcoded boundaries are **absent**. All the literals
  above pass unnoticed. It also pins literal strings (`"(min-width: 640px)"`, `"894"`),
  so changing a constant fails on the test's own literal — channeling a maintainer into
  editing the test rather than fixing the drift.
- `test_collapsed_rails_are_single_clean_chips` drives state by writing
  `documentElement.dataset` directly (`:185-189`), bypassing the toggle handlers, so the
  real interaction path is untested.
- The mirror regex covers only `.raya-course-map`, `.raya-learning-rail`,
  `.raya-learning-shell`; a mirror on `body` or the article element would not be caught.

### Dead-code claim was half wrong (drives Workstream 4)

Each flagged ruleset has two selectors. Measured in headless Chromium across painted
frames mid-transition:

| snapshot | rail has state attr | ancestor form matches | mirror form matches |
|---|---|---|---|
| idle-expanded | false | false | false |
| mid-collapsing | false | **true** | false |
| settled-collapsed | false | false | false |
| mid-expanding | false | **true** | false |

**Ancestor-rooted selectors are LIVE and must not be removed.** Removing
`rendering.py:4166` alone would make the rail render completely empty for the 240 ms
expand window (it is the only rule keeping the chip painted, since `:4156` hides the
header and `:4160` hides the body). Only the nine mirror-rooted second selectors are dead.

### Latent defect found (drives Workstream 5)

At ≥894px, `rendering.py:5355-5359` re-grants `display: block` to
`.raya-learning-rail-body` while `[data-raya-learning-rail-transition="collapsing"]`,
overriding the collapse `display: none` at `:6776-6780` (specificity 0,4,0 vs 0,2,1).
Measured 100 ms after clicking collapse: right rail = **44 × 10,466 px** fixed element.
Currently benign (`visibility: hidden` + `pointer-events: none`, document overflow 0),
but it is a latent full-page click-blocker and contradicts the "single source of collapsed
appearance" comment at `:5353-5354`. The medium band correctly uses `display: none`
(`:6567-6577`).

## Scope

### In scope

**Workstream 1 — Eliminate the width-source mismatch.**
Make the JS rail-state derivation agree with CSS *by construction* by deriving from
`matchMedia` rather than `innerWidth`, in both `shell_geometry.py`'s shared derivation
and any remaining `innerWidth` comparisons. This removes the entire scrollbar-mismatch
failure class rather than patching one engine. Install Firefox and WebKit so the test
matrix covers the engines that expose it.

**Workstream 2 — Close the remaining drift.**
Add `__RAYA_STRUCTURAL_MINUS_PX__` and tokenize the three `639` literals; tokenize the
`1280` literal at `rendering.py:5166`; introduce a token for the `767` boundary and use
it in both `rendering.py:6863` and `shell.py:55`; collapse the triplicated default-state
rule into one shared definition.

**Workstream 3 — Repair the guardrails.**
Tighten the `-transition` exemption to strip only the transition token instead of skipping
the whole line; add absence-assertions that fail on any hardcoded rail boundary; derive
the test's expected boundaries from the constants instead of pinning literals; broaden the
mirror regex beyond the three element classes; add a test that drives collapse through
real button clicks rather than dataset injection.

**Workstream 4 — Prune only what is proven dead.**
Remove the nine mirror-rooted selector *lines* only
(`rendering.py:4157, 4161, 4167, 4182, 4193, 5358, 5364, 6574, 6576`). Keep every
ancestor-rooted selector. Do not use a broad regex sweep: `.raya-course-map[data-raya-course-map-root]`
and `[data-raya-course-map-storage-key]` (`builder.py:2199-2201`) are live attributes with
a confusingly similar prefix.

**Workstream 5 — Fix the latent overlay defect.**
Make the ≥894 collapsing branch behave like the medium band, which uses `display: none`
(`rendering.py:6567-6577`), so the collapsed rail cannot become a full-height fixed
element. The fix must preserve the fade-out behaviour the ancestor-rooted rule exists to
provide (see Workstream 4): if `display: none` at frame 1 would reintroduce the abrupt
vanish that `:5357` was written to prevent, constrain the element's height instead of its
display. Whichever is chosen, the acceptance test is the same — a collapsed rail never
exceeds the viewport height.

**Workstream 6 — Small follow-ups.**
- Restore the gutter assertion to `>= 24` (measured exactly 24.0 px at every width, with
  OpenDyslexic + x-large text, and at 1.25×/2× DPI; it is a fixed rem track with no
  jitter). The pre-refactor contract was `>= 24`; `>= 20` was a needless loosening.
- Dedupe the byte-identical `railState`/`shellState`/`rootState` keys
  (`tests/e2e/test_preview_static_read_path.py:14287-14289`, `:14335-14337`, and the
  course-map equivalents at `:13829-13831`, `:13929-13931`, `:14006-14008`), and fix the
  degenerate conditional at `:21353`.
- Add a `<640` counterpart of the existing `.raya-font-toggle` label rule
  (`rendering.py:6764-6766`) near `rendering.py:4272` so the phone-drawer "OpenDyslexic"
  label stops wrapping to two lines (measured 45.2 px button vs 28 px siblings at
  390/375/320 px). **Do not** shorten the label text — that string is asserted in
  `tests/contracts/test_documentation_surfaces.py:392,395` and
  `tests/contracts/test_static_builder.py:4948,4972` (EN + ES).

**Workstream 7 — Documentation.**
Add a section to `docs/foundation/20_learning_renderer_contract.md` codifying the
invariants: rail geometry lives only in `shell_geometry.py`; collapse state lives only on
`documentElement.dataset`; JS and CSS must derive band membership from the same width
source; no element-level state mirrors.

**Workstream 8 — Record deferred debt.**
Write up two future projects with prerequisites and triggers: asset cache-busting (below)
and extraction of the CSS from `rendering.py`'s ~7,800-line Python string (prerequisite: a
visual-regression / byte-diff safety net; trigger: next structural rail CSS change).

### Out of scope (deferred, with reasons)

**Asset cache-busting — deferred to its own spec.** It is correct work but larger and less
urgent than first assessed:

- The mechanism must be **hashed paths**, not query strings. Measured against the
  production edge three times with never-before-seen query strings: all returned
  `x-cache: HIT` on first request, proving Fastly's cache key for GitHub Pages ignores the
  query string. `?v=` would be *actively worse* than nothing — the browser keys on the
  query string, fetches the "new" URL, receives stale bytes from the query-insensitive
  edge, and re-pins them under a fresh TTL.
- Urgency is modest: the deployed site sends `cache-control: max-age=600`, so staleness
  self-heals in ten minutes. The genuinely unbounded case is the local preview server,
  which sends no cache headers at all (`packages/cli/src/raya_cli/preview.py:7,20`), so
  browsers apply heuristic freshness.
- Real size: ~14 generated assets across 7 emission surfaces (reader, inspection, and 5
  discovery surfaces), ~72 literal test assertion sites, plus hardcoded paths in
  `packages/cli/src/raya_cli/render_debug_report.py:444,1061`.
- A build-order constraint applies: pages are rendered (`builder.py:350-406`) *before*
  assets are written (`:424-431`), so hashes must be computed from generator output
  strings, not from disk. Hashed *directories* additionally fix font URLs embedded inside
  CSS bytes, which no call-site rewrite can reach.
- Asset generation was verified deterministic (two independent builds produced
  byte-identical assets), so content hashing is viable.

**CSS-out-of-`rendering.py` extraction — deferred.** Recorded as known debt in
Workstream 8.

**Right-rail dead drawer path.** `openLearningRailDrawer` (`shell.py:1104-1122`) is never
called, yet its close/focus-trap/scroll-lock/backdrop/CSS all exist. Recorded as a
follow-up decision (remove vs wire) rather than resolved here, to keep this spec focused.

### Non-goals

No behavior changes to rail collapse UX, no new features, no restructuring beyond the
workstreams above.

### Ordering constraints

Workstreams are not independent; two orderings are load-bearing:

1. **Workstream 4 (prune the nine dead mirror lines) must land before the Workstream 3
   exemption tightening.** Tightening the `-transition` exemption first turns the
   guardrail red against the nine selectors that are still present. Prune first, then
   tighten, so the tightened test lands green and stays green.
2. **The Workstream 3 absence-assertions must land before Workstream 2's tokenization.**
   The assertion is the RED proof that the literals exist; tokenizing then turns it green.
   This ordering also guarantees no literal is missed.

## Testing strategy

- Every workstream is gated by the existing e2e rail contract suite, run in the
  **foreground** (never backgrounded).
- Workstream 3 must demonstrate its own value: each repaired guardrail gets a RED proof
  that it fails against the current violating code before it is made to pass.
- Workstream 1 requires a cross-engine run (Chromium + Firefox + WebKit) across the
  boundary band 636-660 px, asserting JS-derived state and CSS-applied appearance agree.
- Workstream 4 requires the mid-transition frame measurements to be preserved as a
  regression test, so a future prune cannot remove a live ancestor selector.
- Workstream 5 requires an assertion that no collapsed rail exceeds the viewport height.

## Risks

- **Tokenizing boundaries touches many CSS sites.** Mitigated by the Workstream 3
  absence-assertions landing first, so any missed literal fails the suite.
- **The `matchMedia` change alters prepaint timing.** `matchMedia` is available at
  prepaint time, but the change must preserve the no-flash guarantee; a prepaint-blocked
  and JS-blocked run is required.
- **Firefox/WebKit may reveal further engine-specific breakage** beyond the scrollbar
  band. That is the point of installing them; any finding is reported, not silently fixed.
